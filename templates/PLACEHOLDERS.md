# Placeholder ทั้งหมดในระบบ ConsDocx

อ้างอิงสำหรับตอนทำเอกสารเพิ่ม (เอกสาร 6, 7, ...) — เอา placeholder ที่มีอยู่แล้วไปใช้ซ้ำได้เลย
ไม่ต้องคิดชื่อใหม่ ถ้าความหมายตรงกับที่มีอยู่แล้ว

รูปแบบ placeholder ในไฟล์ `.docx`: พิมพ์ข้อความ `[ชื่อ_placeholder]` ธรรมดาลงในเอกสาร (มีวงเล็บเหลี่ยมครอบ)
โค้ดฝั่ง JS จะค้นแทนที่ข้อความนี้ด้วยค่าจริงตอนสร้างไฟล์

**ที่มาของค่าตอนสร้างไฟล์:** ทุกช่องอยู่ที่ `forms/main.html` หน้าเดียว (หน้าฟอร์มแยกรายเอกสารถูกยุบ
มารวมหมดแล้ว) ค่าทั้งหมดอ่านจากช่องในหน้านี้ผ่าน `val("g_...")` — ชื่อ id ที่เขียนในตารางข้างล่าง
คือ id ของช่องในหน้านี้

| `[เดือน]` | เดือนที่ออกเอกสาร | 2, 3 | ช่อง "เดือน/ปี" หน้า main (`g_month`) |
| `[ปี]` | ปี พ.ศ. ที่ออกเอกสาร | 2, 3 | ช่อง "เดือน/ปี" หน้า main (`g_year`) |
| `[จำนวนเงินตัวเลข]` | งบประมาณ ตัวเลขพร้อม comma | 3, 4, 5 | ช่อง "งบประมาณ" หน้า main (`g_moneyNum`) ผ่าน `formatComma()` |

หมายเหตุ `[เดือน]`/`[ปี]`: เอกสาร 1, 4, 5 ไม่มี placeholder นี้ในเทมเพลตแล้ว (ใช้ `[วันที่หนังสือ...]` ซึ่งมี

หมายเหตุ `[รายละเอียดโครงการ]`: ตอนนี้มีแค่เทมเพลต 3 ที่พิมพ์ไว้ แต่โค้ดส่งค่าให้ทุกเอกสารผ่าน
`sharedProjectFields()` — พิมพ์ลงเทมเพลตอื่นได้เลยโดยไม่ต้องแก้โค้ด

## เลขที่/วันที่หนังสืออ้างอิง (4 คู่) — ใช้ร่วมกันหลายเอกสาร

กรอกที่การ์ด "เลขที่/วันที่หนังสือที่เกี่ยวข้อง" (`g_orderNo`, `g_orderDate`, `g_letter1No/Date`,
`g_letter2No/Date`, `g_letter3No/Date`) — ชุดเดียวใช้ร่วมกันทุกเอกสาร

| Placeholder | ความหมาย | ใช้ในเอกสาร | ฟิลด์ |
|---|---|---|---|
| `[เลขที่คำสั่งคณะกรรมการจัดทำแบบรูปรายการงานก่อสร้าง]` | เลขที่คำสั่งแต่งตั้งคณะกรรมการ (เอกสาร 2) | 2, 3, 5 | `orderNo` |
| `[วันที่คำสั่งคณะกรรมการจัดทำแบบรูปรายการงานก่อสร้าง]` | วันที่ของคำสั่งนั้น | 3, 5 | `orderDate` |
| `[เลขที่หนังสือขออนุมัติโครงการ]` | เลขที่หนังสือของเอกสาร 1 | 1, 5 | `letter1No` |
| `[วันที่หนังสือขออนุมัติโครงการ]` | วันที่ออกหนังสือของเอกสาร 1 | 1, 5 | `letter1Date` |
| `[เลขที่หนังสือรายงานการจัดทำแบบรูปรายการ]` | เลขที่หนังสือของเอกสาร 4 | 4 | `letter2No` |
| `[วันที่หนังสือรายงานการจัดทำแบบรูปรายการ]` | วันที่ออกหนังสือของเอกสาร 4 | 4, 5 | `letter2Date` |
| `[เลขที่หนังสือขอนำส่งเอกสารการจัดทำโครงการ]` | เลขที่หนังสือของเอกสาร 5 | 5 | `letter3No` |
| `[วันที่หนังสือขอนำส่งเอกสารการจัดทำโครงการ]` | วันที่ออกหนังสือของเอกสาร 5 | 5 | `letter3Date` |

**กลไกเว้นว่าง** (ฟังก์ชัน `docRefNoWithYear()` / `docRefNoOnly()` / `docRefDate()` + ค่าคงที่
`DOC_REF_BLANK` = ช่องว่าง 8 ตัว) — ทุกช่องเว้นว่างได้ ถ้าไม่กรอกจะได้ช่องว่างให้เขียนมือทีหลังแทน:

- เลขที่คำสั่ง (`orderNo`) → `"␣␣␣␣␣␣␣␣/{ปี}"` — เติมปี พ.ศ. ต่อท้ายให้อัตโนมัติ
- เลขที่หนังสืออื่น (`letter1No`, `letter2No`, `letter3No`) → `"␣␣␣␣␣␣␣␣"` เปล่าๆ (เลขที่หนังสือมี
  ส่วนหน้าเป็นชื่อส่วนราชการพิมพ์ไว้ในเทมเพลตอยู่แล้ว จึงไม่เติมปี)
- วันที่ทุกช่อง → `"␣␣␣␣␣␣␣␣{เดือน} {ปี}"` — เติมเดือน/ปีจากช่อง "เดือน/ปี" ให้อัตโนมัติ

**ช่องวันที่พิมพ์ย่อได้** — `ConsDocxMonthYear.formatThaiDate(raw, ปีสำรอง)` ใน `shared/monthyear.js`
แปลงให้เป็นวันที่เต็มภาษาไทยเสมอก่อนใส่ลงเอกสาร รับได้ทั้ง `1/2/2569`, `1-2-69`, `1.2.2569`,
`2569-02-01`, `1 ก.พ. 69`, `1 กพ 2569`, `1 กุมภา 2569`, เลขไทย `๑/๒/๒๕๖๙` → ทั้งหมดได้
`1 กุมภาพันธ์ 2569` — ปี 2 หลักเติม 2500 ให้, ปี ค.ศ. (1900–2200) บวก 543 ให้, ไม่พิมพ์ปีก็ใช้ปีจากช่อง
"เดือน/ปี" ถ้าแกะรูปแบบไม่ออกจะคืนข้อความเดิมที่พิมพ์มา (ไม่แก้ให้เพี้ยน) หน้า main ยังแปลงให้เห็นในช่อง
ทันทีตอนคลิกออกจากช่อง (`input.date-field` + event `blur`)

## เรื่องเดิม / ข้อเท็จจริง (เอกสาร 1 และ 5 เท่านั้น)

| Placeholder | ความหมาย | ค่ามาจาก |
|---|---|---|
| `[PM1]` `[PM2]` `[PM3]` `[PM4]` | ย่อหน้า "เรื่องเดิม" — แต่ละอันอยู่คนละย่อหน้าในเอกสาร | ช่อง "เรื่องเดิม" หน้า main (`g_priorMatter`) |
| `[ข้อเท็จจริง]` | ข้อความ "ข้อเท็จจริง" | ช่อง "ข้อเท็จจริง" หน้า main (`g_facts`) |

**กลไกพิเศษของ PM1-4:** ถ้าผู้ใช้พิมพ์ข้อความเองในช่อง "เรื่องเดิม" ข้อความนั้นจะถูกใส่ใน `[PM1]`
อย่างเดียว ส่วนย่อหน้า `[PM2]`-`[PM4]` (ที่ปกติมีข้อความตัวอย่าง/default อยู่) จะถูก**ลบทั้งย่อหน้าทิ้ง**
ไปเลย ไม่ใช่แค่เว้นว่าง — ถ้าผู้ใช้ไม่พิมพ์อะไรเลย จะใช้ข้อความ default 4 ท่อน (คงที่ในโค้ด `DEFAULT_PM_1`
ถึง `DEFAULT_PM_4`) ใส่ใน 4 ย่อหน้าตามเดิม

เหตุที่ต้องแยกเป็น 4 placeholder แทนที่จะเป็นก้อนเดียว: เทมเพลตต้นฉบับเขียนย่อหน้า "เรื่องเดิม" เป็น
4 บรรทัดแยกกัน (แต่ละบรรทัดอ้างอิงกฎหมาย/มติ/งบประมาณคนละเรื่อง) เวลาผู้ใช้กรอกเอง มักมีแค่เนื้อหาเดียว
เลยยุบเหลือย่อหน้าเดียว (PM1) แล้วลบ 3 ย่อหน้าที่เหลือทิ้ง

ถ้าจะทำ placeholder แบบ "ลบทั้งย่อหน้าถ้าไม่มีค่า" ในเอกสารใหม่ ให้ส่งค่า `null` (ไม่ใช่ `""`) เข้า
`fieldsMap` ตอนเรียก `buildOneDocx()` — โค้ดจะลบ `<w:p>...</w:p>` ทั้งก้อนที่มี placeholder นั้นทิ้งให้

## ข้อความ "ค่าตั้งต้น" ที่โปรแกรมใส่ให้เอง — ออกมาเป็นตัวอักษรสีแดง

ช่องไหนที่ผู้ใช้เว้นว่างไว้แล้วโปรแกรมเติมข้อความให้แทน จะถูกแทนลงเอกสารด้วย **ตัวอักษรสีแดง**
(`<w:color w:val="FF0000"/>`) เพื่อให้เห็นชัดว่าต้องกลับมาตรวจ/แก้ก่อนใช้จริง ถ้าผู้ใช้กรอกเองจะเป็นสีปกติ

ตอนนี้ที่เป็นสีแดงได้: `[PM1]`-`[PM4]` (ข้อความ "เรื่องเดิม" ตัวอย่าง), `[ข้อเท็จจริง]` (ข้อความตัวอย่าง),
และเลขที่/วันที่หนังสือทุกช่องที่เว้นว่างไว้ (ช่องว่าง 8 ตัว + ปี/เดือน-ปีที่เติมให้)

**วิธีทำให้ค่าใหม่เป็นสีแดง:** ห่อค่าด้วย `asDefault(...)` ตอนใส่ลง `fieldsMap` เช่น
`"[ข้อเท็จจริง]": val("g_facts") || asDefault(DEFAULT_FACTS)` — ค่าปกติ (string) ยังใช้ได้เหมือนเดิม
ไม่ต้องแก้อะไร กลไกข้างในคือ `asDefault()` คืน `{ text, isDefault: true }` แล้ว `buildOneDocx()` แกะออก
ส่งต่อให้ `replacePlaceholder(xml, ph, value, isDefault)` ซึ่งจะเรียก `rPrAsDefault(rPr)` ใส่ `<w:color>`
สีแดงเข้าไปใน `<w:rPr>` ของ **เฉพาะรันที่แทนค่าลงไป** เท่านั้น (ข้อความเดิมรอบๆ ในรันเดียวกันไม่เปลี่ยนสี)
และคงรูปแบบเดิมของรัน (ฟอนต์/ขนาด/ตัวหนา) ไว้ครบ

หมายเหตุตำแหน่ง `<w:color>`: ลำดับ element ใน `<w:rPr>` มีผลกับ Word — `rPrAsDefault()` จึงแทรก
`<w:color>` ไว้ก่อน `w:spacing`/`w:sz`/`w:u`/`w:lang` ฯลฯ ให้เอง และลบ `<w:color>` เดิม (เช่น `w:val="auto"`)
ออกก่อนเสมอ

ทั้งหมดอยู่ใน `forms/main.html` (ไฟล์เดียว):

- `sharedProjectFields(data, projectName, monthG, yearG)` — คืน placeholder ชุด
  "ข้อมูลโครงการ" ทั้งหมด (`[ชื่อโครงการ]`, `[รายละเอียดโครงการ]` + เลขที่/วันที่หนังสือ 4 คู่) spread ลงใน
  `fieldsMap` ของทุกเอกสาร — เอกสารใหม่ให้ spread ตัวนี้เข้าไปด้วยเสมอ
- `formatComma(numStr)` — ใส่ comma คั่นหลักพัน เช่น `2256000` → `2,256,000`
- `bahtText(numStr)` — แปลงตัวเลขเป็นข้อความจำนวนเงินภาษาไทย เช่น `2256000` → `สองล้านสองแสนห้าหมื่นหกพันบาทถ้วน`
- `stripActingRank(name)` — ตัดคำนำหน้า/ยศรักษาการ (เช่น "ว่าที่ ร.ต.") ออกจากชื่อ
- `xmlEscape(s)` — escape อักขระพิเศษ (`&`, `<`, `>`) ก่อนแทรกลง XML ของ docx
- `normalizePlaceholderRuns(xml)` — เรียกก่อนแทนที่ placeholder ทุกครั้งเสมอ (สำคัญ ดูหัวข้อถัดไป)

## ข้อควรระวัง: Word อาจตัด placeholder ขาดเป็นหลายส่วนในไฟล์ .docx

เวลาพิมพ์ `[ชื่อ_placeholder]` ลงใน Word แล้ว Word บันทึกไฟล์ บางครั้ง Word จะเก็บข้อความนี้แยกเป็นหลาย
"run" (`<w:r>`) ในไฟล์ XML ข้างใน — มักเกิดตรงรอยต่อภาษาไทย/อังกฤษปนกัน (เช่น `[สูตรค่าK]` ที่มีทั้งไทยและ
อังกฤษ) หรือบางทีก็เกิดกับข้อความไทยล้วนๆ อย่าง `[PM1]` ด้วยเหมือนกัน ถ้าไม่จัดการเรื่องนี้ โค้ดแทนที่
placeholder (`replacePlaceholder()`) จะหา `[ชื่อ_placeholder]` ไม่เจอ (เพราะข้อความไม่ได้อยู่ใน `<w:t>`
เดียวกัน) แล้ว placeholder นั้นจะโผล่ค้างเป็นข้อความ `[...]` เดิมๆ ในไฟล์ที่สร้างออกมา ไม่ถูกแทนที่เลย
(เจอบั๊กนี้จริงกับ `[สูตรค่าK]` ในเอกสาร 5 มาแล้ว)

วิธีแก้: เรียก `normalizePlaceholderRuns(xml)` ก่อนเสมอ (ก่อน loop แทนที่ placeholder ทุกตัว) — ฟังก์ชันนี้
จะไล่สแกน run ทีละตัวแล้วรวม run ที่มี "[" ค้างอยู่ (ยังไม่เจอ "]" ปิด) เข้ากับ run ถัดๆ ไปจนกว่าจะเจอ "]"
ให้กลายเป็น run เดียว ใช้ได้กับ placeholder ทุกชื่อโดยไม่ต้อง hardcode รายชื่อ placeholder ไว้ล่วงหน้า —
ถ้าทำเอกสารใหม่แล้วพบว่า placeholder ตัวไหนไม่ถูกแทนที่ (ยังเห็น `[...]` ค้างในไฟล์ที่สร้างออกมา) ให้สงสัย
เรื่องนี้ก่อนเป็นอันดับแรก แล้วเช็คว่าเรียก `normalizePlaceholderRuns()` ก่อน loop แทนที่หรือยัง

## ขั้นตอนเพิ่มเอกสารใหม่ (เช่น เอกสาร 6)

1. สร้างไฟล์ `.docx` ต้นแบบใน `templates/` แล้วพิมพ์ placeholder ที่ต้องการ — **ใช้ชื่อ placeholder ที่มีอยู่แล้วในตารางข้างต้นถ้าความหมายตรงกัน** (เช่น `[ชื่อโครงการ]`, `[เดือน]`, `[ปี]`) เพื่อให้ปุ่ม "สร้างไฟล์ทั้งหมด" ที่หน้า main กรอกให้อัตโนมัติได้เลยโดยไม่ต้องแก้โค้ดเพิ่ม
2. เพิ่ม `TEMPLATE_N_BASE64` ในไฟล์ `forms/main-template-data.js` (1 บรรทัด = 1 เอกสาร ตามลำดับ N) —
   **ต้อง regenerate base64 จากไฟล์ `.docx` ทุกครั้งที่แก้เทมเพลต** ไม่งั้นแอปจะยังใช้เนื้อหาเก่าอยู่
   (แอปไม่เคยอ่านไฟล์ `.docx` ตอน runtime เลย อ่านจาก base64 ในไฟล์นี้อย่างเดียว)
3. เพิ่มรายการ + ปุ่ม "สร้างไฟล์" ใน `<ul class="doclist">` ที่ `forms/main.html` (ใส่ `data-doc="N"`)
   แล้วเพิ่มฟังก์ชัน `buildDocN()` (ดูรูปแบบจาก `buildDoc1`-`buildDoc5`) — อย่าลืม spread
   `sharedProjectFields(...)` ไว้บนสุดของ `fieldsMap` และลงทะเบียนใน `DOC_INFO`
4. ถ้ามีช่องกรอกใหม่ ให้เพิ่ม `<input id="g_...">` ในการ์ดที่เกี่ยวข้อง แล้วใส่ id ลงใน `AUTOSAVE_FIELDS`
   ด้วย ไม่งั้นค่าที่กรอกจะไม่ถูกจำไว้ตอนปิดหน้า
5. ถ้าค่าไหนเป็น "ค่าตั้งต้นที่โปรแกรมใส่ให้เอง" ให้ห่อด้วย `asDefault(...)` จะได้ออกมาเป็นตัวอักษรสีแดง
